---
title: "Identity resolution"
description: "How Sayvy AI decides which contact a message or call belongs to."
---

When a message arrives, Sayvy AI looks for an existing contact to attach it to. If none matches, it creates one. The match is made on a single identifier per channel, stored in the contact's phone number field.

| Channel | Identifier | Example |
|---|---|---|
| WhatsApp | The sender's WhatsApp number, digits only, as WhatsApp sends it | `919876543210` |
| Instagram | `ig_` followed by the sender's Instagram ID | `ig_17841400000000000` |
| Email | The sender's address in lowercase | `asha@example.com` |
| Web widget | `web_` followed by the visitor's session ID | `web_5f2c9a` |

Each identifier is unique in a workspace, so the same WhatsApp number always lands on the same contact.

## Web visitors

People who chat in your web widget are anonymous. Each session creates a contact named "Web Visitor" with a short code, tagged `web_widget`. If the visitor gives a phone number or email in the chat, it isn't used to link them to an existing contact.

## One person, several contacts

Contacts are never merged. Someone who messages you on WhatsApp and later on Instagram becomes two separate contacts, each with its own history. There's no merge tool yet.

To keep track of these people, add a note or a custom field on each contact that points to the other one. That way your team has the full picture, even though the agent treats them as two people.

## Contacts you add yourself

When you add a contact by hand or by import, the phone number is stored exactly as you type it. A WhatsApp message from that person only matches if the number is written the way WhatsApp sends it: country code and digits, no `+`, no spaces. See [Import and export](/documentation/crm/import-export).
