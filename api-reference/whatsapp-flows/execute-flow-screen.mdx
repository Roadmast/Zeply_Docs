---
title: "Execute flow screen"
sidebarTitle: "Execute flow screen"
api: "POST /api/v1/whatsapp-flows/{flow_id}/execute"
description: "Simulate or run a server-side dynamic data exchange execution for a WhatsApp Flow screen"
---

Executes server-side logic for a specific WhatsApp Flow screen during a dynamic data exchange action. This endpoint processes screen input payloads submitted by users inside WhatsApp, executes business logic, and returns the response state payload or routing information for the subsequent screen.

---

### Authentication

This endpoint requires Bearer token authentication.

```http
Authorization: Bearer <token>
```

| Header | Type | Required | Description | Format |
| :--- | :--- | :--- | :--- | :--- |
| `Authorization` | `string` | **Yes** | Scoped organization API key or Bearer JWT token | `Bearer <token>` |

---

### Input parameters

#### Path Parameters

<ParamField path="flow_id" type="string" required>
  Unique UUID identifier of the WhatsApp Flow. Example: `1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d`.
</ParamField>

#### Header Parameters

<ParamField header="Authorization" type="string" required>
  Bearer token for authentication. Format: `Bearer <token>`.
</ParamField>

#### Request Body

<ParamField body="screen_id" type="string" required>
  The identifier of the screen currently triggering the execution (e.g., `"APPOINTMENT_SELECTION"`).
</ParamField>

<ParamField body="action" type="string" default="data_exchange">
  The action triggered by the flow screen event. Usually `"data_exchange"`.
</ParamField>

<ParamField body="data" type="object" default="{}">
  Key-value pair dictionary containing user responses, form values, and input arguments from the active screen.
</ParamField>

---

### Response Fields

<ResponseField name="screen_id" type="string">
  Identifier of the next screen to present to the user, or `null` if remaining on the current screen or concluding the flow.
</ResponseField>

<ResponseField name="data" type="object">
  Key-value mapping of dynamic response variables to render on the client screen (e.g., available appointment slots, pricing quotes).
</ResponseField>

<ResponseField name="error_message" type="string">
  Optional error message to display in the Flow client if validation or processing fails. Returns `null` on success.
</ResponseField>

```bash cURL
curl -X POST "https://api.pingr.ai/api/v1/whatsapp-flows/1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d/execute" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "screen_id": "APPOINTMENT_SELECTION",
    "action": "data_exchange",
    "data": {
      "service_type": "consultation",
      "preferred_date": "2026-09-15"
    }
  }'
```

```python Python
import requests

url = "https://api.pingr.ai/api/v1/whatsapp-flows/1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d/execute"

headers = {
    "Authorization": "Bearer <token>",
    "Content-Type": "application/json"
}

payload = {
    "screen_id": "APPOINTMENT_SELECTION",
    "action": "data_exchange",
    "data": {
        "service_type": "consultation",
        "preferred_date": "2026-09-15"
    }
}

response = requests.post(url, json=payload, headers=headers)
print(response.status_code)
print(response.json())
```
